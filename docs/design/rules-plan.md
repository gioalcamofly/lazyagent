# Rules catalog: implementation plan

- **Status:** Accepted (2026-10-24; Q-R1-Q-R26 answered, all as recommended, notes on Q-R7 and Q-R24). Each phase gets an "As landed" note in §5 when it merges.
- **Proposal:** [0014-rules-catalog.md](../proposals/0014-rules-catalog.md). This plan does not repeat its rationale. It covers only what to build, where, and how to prove it. Open questions Q-R1-Q-R26 and their answers are in the proposal; the phases below follow them.
- **Base:** `develop` **after I4e** (`inbox-i4e-home-ux-fixes`, in progress, touches `engine/status.py` and `desktop/crates/app/src/home_view.rs`). R1 must not start before I4e has merged: R1's oracle is the final §3 table.
- **Hard rule:** no LLM at evaluation time, in any phase. The only LLM step is authoring (R7), and its output is validated, previewed and accepted by the user before the engine writes it.
- **Byte-identical:** every golden fixture in `tests/protocol/fixtures/` and every existing engine test stays unchanged through R1-R5 unless a phase says otherwise. New output fields are opt-in (`status_list {fields}`).

## 4. Test strategy

- **Oracle (R1).** `tests/engine/rules/oracle.py` is today's `derive()` verbatim. `test_oracle.py` runs every golden derivation case and 10 000 `Facts` from a seeded generator (agents' statuses, PR states, reviews, mergeable, checks, gestures, claims, holds, delegations, trackers, reports, queue items, ages) through both and asserts equal `Derived`. Kept until R2 removes the old code from the engine; the oracle file itself stays as a regression test of the built-in catalog.
- **Byte-identical.** No fixture under `tests/protocol/fixtures/` changes in R1, R3 (no `[*.qa]`), R4 (nothing configured) or R5 (no attestations). R2 adds fixtures for new methods only; the built-in merge becoming an item (Q-R22) is the one intended change, with its fixtures regenerated in R2 and called out in the PR.
- **Language.** Precedence, Kleene tables, unknown never matching, type errors with suggestions, size and depth caps, RE2 subset checks.
- **No network.** Actions artifacts and logs from fixtures through the existing fake `gh`.

## 5. As landed

### R1 as landed

Branch `rules-r1-catalog-evaluator`. A pure refactor: no fixture, no existing test and no output changed; no user rules, no new method, MCP tool, event or desktop change.

- **Modules.** `engine/rules/lang.py` (tokenizer, recursive-descent parser with the precedence of the proposal, type check, compile to closures, Kleene evaluator), `engine/rules/facts.py` (the registry), `engine/rules/catalog.py` (`[[rule]]` and `[[kind]]` loader, `Catalog.derive`, `kinds_of`), `engine/rules/__init__.py` (`builtin()`, compiled once), `engine/rules/builtin.toml` (package data: hatch ships every file under `src/lazyagent`, and `test_lang.py` builds the wheel and reads the file back from it). `concepts.toml`, `doc.py` and `preview.py` come with R6/R7.
- **Grammar.** As Q-R1: literals (text, numbers, durations `90s` `10m` `24h` `7d` in seconds, `true`/`false`, literal lists), `== != < <= > >=`, `in`, `not in`, `subset`, `known()`, `unknown()`, `empty()`, `not`/`and`/`or`, parentheses, `#` comments. Two additions the built-in table needed: `+` joins text (a number is written as digits), and the choice `c ? a : b` (text only; it takes `a` only when `c` is true, so unknown picks `b`, like a rule that does not match). Comparisons do not chain. A mixed `and`/`or` without parentheses compiles with a warning (none in the built-ins). Caps: 2000 characters, depth 32, 256 nodes. Type errors name the fact or value and suggest the closest (`pr.review is never 'aproved'; did you mean 'approved'?`).
- **Unknown.** A comparison, a `+`, or a function of an unknown is unknown, except `with()` (an unknown detail reads as empty) and `known()`/`unknown()`. A rule matches only on `true`. An output that comes out unknown reads as empty text, no level, `false`, or ball `stalled` (never reached by the built-ins: the oracle would show it).
- **Facts.** 59 facts, two scopes: `row` (from `status.Facts`, for row rules) and `item` (an actionables `Place` and, for the agent kinds, one agent). Each has a type, lower-case values for enums, a phrase (a noun phrase for now: the generated sentences are R6's), source, freshness and cost; all R1 facts are `free` or `poll`. Facts are memoised per row per pass. Facts the later phases bring (`tracker.qa`, `ci.failing_tests`, `ci.unrelated`, `decisions.*`, `presence` …) are not registered yet: they join with their phases. Additions to the proposal's list that today's table reads: `agents.idle`, `agents.first_running`, `config.stalled_after`, `queue.enabled`, `hold.note`, `delegation.agent`/`.fact`, `gesture.how`/`.waiting`/`.source`, and in the item scope `agent.status`/`.detail`/`.id`, `place.is_orchestrator`, `ci.pr_red`. `ci.first_failing` is the PR's first failing check on rows (as before) and the red Actions run's title, else that check, on inbox items (as before).
- **Functions.** `with`, `clip`, `park_text`, `waiting_text`, and `agents.detail_of("<status>")` (a literal status, checked against the enum). `ci.failing_tests_of` is R4's.
- **`then`.** `ball`, `level`, `state`, `blocks_agent`, `suggestion`, each also as `<field>_expr` (the proposal's `state_expr`, generalised: the queue rule takes its level from `items.top.level`, the label its ball from `gesture.ball`); `inherit = ["ball"]` (park) or `["state"]` (label) takes the field from the first matching rule below. **No default level in R1**: a rule without `level` has none, as today's label and reported-ball rows (the proposal's "default round" applies to user rules, R2). `verb`, `action` and `item` are not in R1's catalog (R2/R6).
- **Rules.** 35 rules for the 16 numbers, in today's order, ids from the proposal where it names them (`closed.merged`, `queue`, `merge`, `park`, `label`, …). Where one old branch had two numbers it is two rules (`reported_others` 10 / `reported_ball` 12; `tracker_you` 3 / `tracker_others` 10 / `tracker_ball` 12). `locked = true` marks the prefix (`closed.*`, `park`, `queue`, `claim`, `hold`, `held`, `delegated`); it has no effect until R2. The "no queue" branches are rules guarded by `not queue.enabled`; `items.*` are unknown without a queue.
- **Kinds.** The 14 kinds in their old order with level, title, rank and `blocks_agent`; `actionables.KINDS` is built from them (claims.py still registers `delegation` in code, after them). A `detector` names the code that finds candidates: `agents`, `pr` and `actions` kinds carry the condition and the state text and are evaluated per agent / per place; `exits`, `jobs`, `tracker`, `report`, `decision` stay fed by events or their stores (exits and jobs take their state text from the catalog). Ids, labels, details and runs stay in code.
- **`derive()`** in `engine/status.py` is one call into the catalog; `_derive_tail` and `_NEEDS_YOU` are gone from the engine. `Facts`, `Derived`, `fingerprint` and the row are unchanged.
- **Oracle.** `tests/engine/rules/oracle.py` is the old `derive`/`_derive_tail` verbatim (with copies of the constants they read). `test_oracle.py`: every case of `test_status.DERIVATION` (at two ages), 10 000 `Facts` from a seeded generator (agents, PR states incl. odd ones, checks, reviews, mergeable, reviewer counts, queue items, claims, holds, holders, delegations, trackers, reports, gestures with every park end, merged-into, activity, ages, stalled thresholds; the test also asserts that the samples reach every one of the 35 rules), and a run of `tests/engine`, `tests/protocol`, `tests/contract`, `tests/test_mcp_status.py` and `tests/test_status_cli.py` in a subprocess with `oracle_plugin.py`, which checks every `status.derive` call those suites make against the oracle (about 1 600 calls per run, the count moves a little with the projection's coalescing; no mismatch). A deliberate one-word change to a built-in state fails it.
- **Benchmark.** `test_bench.py`: 100 fixed seeded rows, 3 warm-up passes, the **median of 31 passes**, budget 2 ms × a factor (1 locally, 5 when `CI` is set, or `LAZYAGENT_BENCH_FACTOR`). GC off while timing; up to 5 rounds, the first under budget passes (noise only adds time, so a busy runner gets more chances and a real regression fails all five). Measured locally, quiet machine: catalog 0.5-0.8 ms, old `derive` 0.2-0.33 ms (about 2.5× slower, well inside the budget); with the whole suite and `cargo test` running beside it, 1.0-1.7 ms.
- **Tests.** `uv run pytest`: 2433 passed, 34 skipped (102 new: `test_lang.py` 60, `test_oracle.py` 41, `test_bench.py` 1). Desktop `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (213 passed) unchanged and green; no file under `tests/protocol/fixtures/` changed.
